# 2.0.18 ページごとの用紙・向き

2026-09-26。混在PDFを印刷すると全ページがA3になるとの報告に対応。

## 原因と変更

従来は、印刷プレビューを開いた時に閲覧中のページから用紙・向きを1つ選び、すべてのページへ適用していた。原本のページ寸法自体は正しく取得できていた。

- 「ページごとに原本の用紙・向きに合わせる」を追加し、原寸・指定倍率／用紙に合わせるモードでは既定でオンにした。手動で用紙を固定する場合はオフにする。
- プリンターの対応用紙から原本の寸法に合うものを選び、そのページの向きに設定する。PDFの小数誤差とドライバーの1/100インチ単位を考慮し、短辺・長辺それぞれ2mm未満を照合条件にして最も近い用紙を選ぶ。
- 用紙・向きごとの実際のドライバーの印刷可能範囲を使い、プレビューと出力設定を一緒に作る。同じ用紙・向きの寸法取得は再利用する。
- 印刷ではQueryPageSettingsを使い、各面を描く前に対応するPageSettingsを指定する。[Windowsのページ別設定の仕様](https://learn.microsoft.com/en-us/dotnet/api/system.drawing.printing.printdocument.querypagesettings?view=windowsdesktop-10.0)に沿う。
- 原本に対応する用紙がない場合はページ番号を示して止め、無断で別の用紙に置き換えない。手動の用紙指定へ切り替える案内を表示する。
- 両面では用紙・向きの切替に必要な空白裏面を挿入し、異なる用紙のページを同じ紙の表裏に配置しない。追加した面数はプレビューに表示する。
- 2ページ／枚・4ページ／枚・小冊子・ポスターは従来どおり手動指定の用紙を使う。

## 検証

提供された29ページのPDFを読み取り、修正前はA3ページからプレビューを開くと全ページがA3になることを回帰テストで確認。修正後は次の内訳に一致した。

| 用紙 | 原本 | プレビュー・Windows印刷出力 |
| --- | ---: | ---: |
| A4 縦 | 17 | 17 |
| A4 横 | 3 | 3 |
| A3 横 | 7 | 7 |
| A3 縦 | 2 | 2 |

Microsoft Print to PDFへの実際の印刷処理で29ページを出力し、PDFiumと独立したpypdfでも寸法を照合。最大差は約0.085mmで、原本の端数とドライバーの用紙寸法の差によるもの。原寸100%の配置を維持する。実物の紙の寸法誤差を測った値ではない。A3横のプレビューと出力画像も目視確認した。

回帰テストは15件。用紙・向き・倍率・ページ順・範囲指定・未対応用紙・両面の空白裏面・固定用紙への切替・2ページ／枚・回転済み原本を検証した。既存の自己42件、UI149件、起動57件と合わせて263件成功。`scripts/build.ps1 -Test` に混在用紙の検証を組み込んだ。通常は同梱の確認用PDF、`AIRYVIEW_MIXED_PDF` が指定された場合だけ外部の検証対象を使う。

利用者の原本・出力コピー・画面画像はGit外の検証領域にのみ置き、ソースや配布物へ含めない。検証証跡は `artifacts/mixed-paper-user-29-pages.csv`、`artifacts/mixed-paper-user-test-results.txt`、`artifacts/mixed-paper-final-build.log`。物理プリンターへの印刷は行っておらず、実機の給紙・両面処理はドライバーと用紙トレイの設定に依存する。
