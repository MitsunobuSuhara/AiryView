# PDF処理の保護（2.1.72）

PDFの解析・描画・文字取得・回転・書き込みは、本体とは別のWindows AppContainerで行う。本体はPDFiumを読み込まない。編集・署名用のPythonヘルパーも同じ隔離方式で起動する。隔離の開始に失敗しても、通常権限で処理する経路へ切り替えない。

## 権限と受け渡し

- 文書・ヘルパー呼出しごとに異なるAppContainer SIDを作る。他の文書・署名処理の作業ファイルも共有しない。
- ネットワーク能力を与えない。署名検証は従来どおりオフラインで行い、オンライン失効確認の未実施を表示する。
- 元の文書や保存先のACLは変えない。選択された入力を専用領域へ複製し、保存結果だけを本体が指定先へ移す。秘密鍵ファイルも署名操作に必要な呼出しだけに渡す。
- 本体の環境変数は引き継がず、Windows起動に必要な項目と専用作業先だけを渡す。標準入出力と診断出力は分離する。
- Job Objectで子プロセスの生成を禁止し、本体終了時はワーカーも終了する。終了を待って専用領域とプロファイルを削除する。
- 保存結果は開いたハンドルの実際のパスとハードリンク数を確認する。隔離外を指すリンクを経由して本体にファイルを読ませない。保存先はワーカーの応答で変更せず、一時ファイルを完成してから置き換える。

## 実行機能

PDFium通常版を使用し、V8版は使用しない。文書・ページのJavaScriptや外部アクションを実行するAPIは呼ばない。PDF内リンクは文書内のページ移動だけを許し、URI・外部ファイルの起動は拒否する。添付ファイルを自動実行・自動展開しない。

## 上限

| 対象 | 上限 |
| --- | --- |
| PDF入力・保存結果 | 128 MiB |
| ページ数 | 10,000 |
| 1ページの取得文字数 | 200,000 |
| 描画画像 | 24,000,000画素 |
| ワーカー1プロセスのメモリ | 2 GiB |
| 1回のPDF操作 | 60秒 |
| Pythonヘルパー呼出し | 3分 |
| PDF IPCのフレーム | 192 MiB |
| ヘルパーの要求・応答 | 各8 MiB |

上限や異常終了はエラーとして扱い、未完成の結果で既存保存先を上書きしない。

## 印刷

本体でPDF由来のネイティブ描画命令を再解釈しないため、隔離先から寸法を検証した画素だけを受け取り、従来の用紙・配置計算で印刷する。印刷時も最大24メガピクセルとし、それを超える場合は画像を縮小する。従来のベクトル直接印刷とは異なるため、極端な拡大印刷や微細な線・文字は実機での見え方を確認する必要がある。

## 更新と検証

- PDFium 158.0.8111、pypdf 6.21.2、cryptography 50.0.2、pyHanko 0.38.0、pyhanko-certvalidator 0.33.0、Pillow 13.0.0、ReportLab 5.1.0へ更新。
- 間接依存もaiohttp 3.14.5、certifi 2026.10.23、multidict 6.9.1、setuptools 84.2.1へ更新。その他はロックファイル参照。
- 2026-10-25時点のNuGet監査と、ロックされたPython依存33部品のpip-auditで既知脆弱性の報告なし。未発見の欠陥がないという保証ではない。
- `--security-test`で、実際の権限トークン、私有ファイルの読書き拒否、別文書へのアクセス拒否、通信拒否、本体がPDFiumを読み込まないこと、時間制限、異常終了後の復帰、保存・署名・印刷アダプター等を検証する。
- Python依存のビルドには`./scripts/build-pdf-helper.ps1`を使う。バンドルPythonのSSLが必要とする拒否CAデータが存在する場合は同梱し、証明書の信頼設定を弱めない。

依存更新は自動ではない。更新候補と公開済み脆弱性を確認し、閲覧・編集・暗号化・署名・印刷の互換性を検証してから配布する。PDF以外の画像デコーダー等まで隔離したという意味ではない。

参考: [MicrosoftのAppContainer解説](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)、[PDFium配布元](https://www.nuget.org/packages/bblanchon.PDFium.Win32)。
