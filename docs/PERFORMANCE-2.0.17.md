# 2.0.17 初回表示の段階的な切替を減らす

2026-09-26。利用者の「開くときの一瞬の引っかかり」「閉じるときのような滑らかさ」に対する変更。

## 確認できたこと

2.0.16相当の処理に回帰テストを追加し、次の3件が失敗することを確認した。

- 1600×900のPNGは読込完了時点では倍率100%で、その後のDispatcher処理で画面幅へ縮む。
- 表示中の同じPDFを開き直すとページのImageを破棄し、画像を再生成する。
- 同じサイズのPDF描画要求が重なると、1ページを2回処理する。

記録: `artifacts/smooth-open-before.txt`。これらが実利用の引っかかりの全原因とは断定しない。

## 変更

- ファイル指定起動では表示先のHWNDを非表示のまま作り、画像・文章、またはPDFの最初のページのビットマップを準備してからShowする。複数ファイルは最初の1件を表示した後に残りを開く。
- パスワード入力とエラー通知では先に親ウィンドウを表示する。アプリ単独起動の案内画面は維持する。
- 画像の初回フィットを読込完了時／Loaded時に実行し、最初の描画フレームまでに倍率を確定する。最小化等で寸法が取れない場合の再試行は残す。
- 同じタブの再表示では内容・選択・編集位置を維持する。別の既存タブへ移る場合もSelectionChangedとの二重処理を防ぐ。
- PDFのページ・幅・高さが同じ進行中の描画Taskを共有する。古い表示要求の結果で新しい画面を上書きしない判定は維持する。

固定時間の待機、フェード演出、常駐プリロード、原本画質の削減は追加していない。初回表示に必要な読込時間そのものは残る。

## 検証

自己テスト42件、UIテスト149件、起動テスト57件、合計248件成功。PDF/PNG/JPEG/TXT/MDの通常・最大化起動で、IsVisibleがtrueになる時点の内容の準備を確認。画像は最初のCompositionTarget.Renderingから幅が合うことも確認した。元の入力なし表示・最小化復帰・印刷・編集・回転等の検証も成功。
